AI Workshop Attendance App

Draft v1.0 09 October 2026 Owner: Product + Engineering MVP

A fast, auditable attendance system for live AI workshops. Facilitators create sessions, participants check in with minimal friction, and organizers monitor and export verified attendance in real time.

Source and assumption

This PRD is derived from the repository README and current Schoolnet interface. The existing build is a static service overview, so the product behavior below is a proposed MVP pending stakeholder validation.

01 Product definition

Problem

Workshop teams often rely on paper sheets, chat messages, or spreadsheets to record attendance. These methods slow down entry, allow duplicate or unverifiable records, and make post-event reporting labor intensive.

Product outcome

< 15 sec
Median participant check-in
≥ 98%
Accurate attendance records
Live
Facilitator attendance count
1 click
CSV report export

Goals

  • Make participant check-in quick on ordinary mobile browsers, with no app installation.
  • Give facilitators one live source of truth for present, absent, late, and corrected records.
  • Preserve a clear audit trail for manual changes.
  • Produce reusable attendance reports for Schoolnet operations and workshop follow-up.

Non-goals for MVP

  • Biometric identity verification, facial recognition, or continuous location tracking.
  • Learning management, assessments, certificates, or content delivery.
  • Native iOS or Android applications.
  • Automated payroll, billing, or government compliance submissions.

Design principle

The participant path must tolerate low bandwidth and small screens. The facilitator path must remain useful while projected or used from a laptop during a live session.

04 Core experience

Participant check-in

→ → → →
Step 1 · Open

The participant scans the displayed QR code or opens its short link. The page loads the workshop and session name without requiring an app.

Step 2 · Identify

The participant enters the roster identifier chosen by the program, such as email, phone number, or registration ID.

Step 3 · Validate

The service verifies that the session is open, the identifier is eligible, and no accepted record already exists.

Step 4 · Record

The service stores server time, resulting status, source, and session reference as one atomic attendance event.

Step 5 · Confirm

The dashboard count updates and the participant receives a clear success state. A repeat submission returns the original result instead of creating a duplicate.

1 / 5

Facilitator session operation

→ → → → →
Step 1 · Prepare

The facilitator selects the workshop, verifies the roster, and creates the day or time-slot session.

Step 2 · Open

The facilitator opens check-in and displays the generated QR code. The system records the opening time and grace threshold.

Step 3 · Monitor

Live counts show present, late, pending, and walk-in totals. Search helps answer participant questions without interrupting the session.

Step 4 · Resolve

The facilitator handles unmatched identifiers and may apply a manual status with a required reason. Every change enters the audit log.

Step 5 · Close

Closing disables new participant submissions. Remaining roster members resolve to absent, while authorized corrections remain available.

Step 6 · Export

The facilitator or admin downloads a consistent CSV report and can reopen the dashboard later without changing recorded timestamps.

05 System and data

Proposed service boundary

→ → → →
Step 1 · Clients

A lightweight public check-in page and an authenticated facilitator console call the same backend contract.

Step 2 · API

The API owns validation, idempotency, status calculation, and response shapes. Client code does not decide attendance truth.

Step 3 · Authorize

Role checks protect workshop management, corrections, audit access, and export while the session token limits public check-in.

Step 4 · Persist

A relational store keeps workshops, sessions, participants, attendance records, and append-only audit events with referential integrity.

Step 5 · Report

Authorized exports are generated from canonical records, use server-side filtering, and record the export actor and time.

08 Delivery plan

→ → → →
Gate 1 · Validate

Confirm identifier choice, roster format, workshop scale, retention policy, late rules, and facilitator roles with operations.

Gate 2 · Build

Implement authentication, workshop and roster setup, session lifecycle, participant check-in, live dashboard, corrections, audit trail, and CSV export.

Gate 3 · Pilot

Run one real workshop with a trained facilitator, observe entry behavior, reconcile a manual backup, and collect timing plus failure data.

Gate 4 · Harden

Resolve pilot issues, complete load and accessibility testing, add operational monitoring, and document incident and data recovery procedures.

Gate 5 · Launch

Release to approved workshop teams, review success metrics weekly, and prioritize follow-up items from measured participant and facilitator friction.

1 / 5

Launch acceptance

  • All must-have requirements pass end-to-end acceptance tests.
  • A pilot workshop completes with reconciled totals and no lost canonical records.
  • Security, privacy, accessibility, and browser reviews have named approvers.
  • Monitoring covers failed submissions, elevated latency, export failures, and unexpected duplicate conflicts.
  • Facilitator quick-start guidance and a manual fallback procedure are available.

Open questions

  • Should a workshop contain multiple attendance sessions across several days?
  • Which identity provider should administrators and facilitators use?
