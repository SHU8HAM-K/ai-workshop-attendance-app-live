Student Workshop Attendance System

Draft v1.009 October 2026Source: project concept imageMVP

A simple admin-led system for recording student attendance in workshops, organizing records by calendar date, measuring time spent, and turning attendance data into useful analytics and reports.

Grounded scope

This PRD uses the seven capabilities shown in the shared concept image: admin student management, attendance status, calendar, student list, time spent, analytics graphs, and reporting. Details not shown in the image are marked as decisions to confirm.

01 Product vision

Problem statement

Workshop teams need one reliable place to know which students joined, whether their attendance has been marked, how long they participated, and what the attendance pattern looks like over time. Manual lists and spreadsheets make daily marking, review, and reporting slow and error prone.

Product goal

Give an authorized administrator a fast attendance workspace that connects each student to a workshop date, a clear status, a participation duration, and an exportable record.

MVP success

  • An admin can create and maintain the workshop student list without editing a spreadsheet.
  • An admin can complete daily attendance and immediately see how many students are Present, Absent, or still Unmarked.
  • Time spent and historical attendance are visible per student.
  • Analytics totals match the underlying student records and reports.

Included in MVP

  • Secure admin portal.
  • Student list with add, edit, search, and remove actions.
  • Workshop calendar with daily attendance status.
  • Unmarked, Present, and Absent states.
  • Time spent per student and per session date.
  • Attendance analytics graphs.
  • Downloadable and printable reports.

Outside the confirmed scope

Student self check-in, QR codes, biometrics, notifications, certificates, payments, and learning content are not shown in the concept image. They should not enter the MVP unless the project owner adds them.

03 Product structure

→→→→→→
Step 1 · Sign in

An authorized administrator enters the protected workspace.

Step 2 · Portal

The home dashboard summarizes today's attendance and highlights records that are still Unmarked.

Step 3 · Students

The admin adds, edits, searches, or removes students from the workshop list.

Step 4 · Calendar

The admin chooses a workshop date and sees its attendance completion status.

Each student receives one status for the selected date, plus participation times when available.

Graphs summarize attendance rate, status distribution, trends, and time spent.

The admin filters a date range and produces a downloadable or printable attendance report.

04 Attendance workflow

Unmarked

Default state. The admin has not yet made a decision.

Present

The student attended on the selected workshop date.

Absent

The student did not attend on the selected workshop date.

→→→→→
Step 1 · Choose date

The admin selects the workshop date from the calendar.

Step 2 · Load list

The system shows all active students. New daily records start as Unmarked.

Step 3 · Mark

The admin marks each student Present or Absent. Bulk marking may speed up large workshops while preserving individual editing.

Step 4 · Add time

For Present students, the admin records start and end time or a total duration. The exact method is a product decision.

Step 5 · Review

A completion summary shows totals and lists any students who remain Unmarked or have invalid times.

Step 6 · Save

The date record is saved, the calendar indicator updates, and analytics recalculate from the stored records.

1 / 6
Required rule

Unmarked must remain different from Absent. The system must never convert an incomplete admin action into an absence without a visible confirmation.

Student record

Minimum proposed fields are student ID, full name, class or group, contact or registration reference, workshop, active status, and created date. Exact required fields must match the Schoolnet source data.

Attendance record

Minimum proposed fields are student ID, workshop date, status, start time, end time, calculated duration, notes, marked by, and last updated time.

07 Quality and data rules

AreaRequirement
AccuracyOne attendance record per student per workshop date. Dashboard, calendar, graphs, and reports use the same canonical record.
UsabilityAn admin can mark a typical day's attendance without navigating away from the student list.
PerformanceStudent lists and calendar views should become usable within 3 seconds on the target Schoolnet network.
AccessibilityAll actions support keyboard use, visible focus, text labels, and status cues that do not rely only on color.
SecurityProtected access, role checks, encrypted transport, safe session handling, and audit logging for sensitive changes.
PrivacyCollect only required student information and define access, retention, export, and deletion policies before launch.
RecoveryAccidental student removal must not delete historical attendance. Corrections must be traceable.
Data invariant

time_spent = end_time - start_time when time boundaries are used. Absent and Unmarked records must not carry participation duration.

08 Delivery and decisions

Suggested MVP delivery order

→→→→
Phase 1 · Foundation

Confirm data fields, roles, workshop date model, and time-spent method, then implement admin authentication and the base data model.

Phase 2 · Students

Build the student list with add, edit, search, filter, and safe removal.

Phase 3 · Attendance

Build the calendar, daily marking interface, three-state model, time spent, validation, and correction history.

Phase 4 · Insights

Add dashboard totals, graphs, student history, filtered reports, and export.

Phase 5 · Pilot

Run one real workshop day, compare the results with a manual backup, and resolve usability or accuracy problems before wider use.

1 / 5

Decisions to confirm

  • Which fields uniquely identify a student?
  • Does one project contain one workshop or several workshops?
  • Are workshop dates created in advance or generated from a schedule?
  • Is time spent entered manually, captured from check-in and check-out, or calculated another way?
  • Can coordinators edit attendance, or is editing restricted to administrators?
  • Which report formats are required: CSV, PDF, print, or all three?
  • How long should student and attendance records be retained?
MVP launch gate

The product is ready for pilot when an admin can manage students, complete one date's attendance, record valid participation time, review analytics, and export a report whose totals match the attendance list.
